# 金庸全集基础图谱阶段总结与交接

本文档面向后续接手本项目的人类或 AI agent。目标不是重复单次实验日志，而是把当前阶段的目标、过程、经验、教训、现状和下一步路线整理成可快速继承的工作共识。

## 一句话结论

金庸全集这一轮基础图谱已经跑完，并且已经有明确价值。

- 它不是最终严谨知识图谱。
- 它已经足够作为下一阶段后处理、证据化查询、跨作品研究和方法迁移的底座。
- 现阶段最值得做的不是继续烧 token 跑更多同类任务，而是整理、对齐、裁剪、验证研究问题。

## 当前目标定位

这一轮工作的真正目标，不是构造一张立刻可以当百科用的终局图谱，而是建立一个：

1. 可复用的结构化材料底座
2. 可审计的检索与回答路径
3. 可持续后处理的中间产物体系
4. 可外推到其他语料的实验方法

因此当前图谱应被定位为：

- 第一阶段高召回图谱底座
- 文学研究与证据检索的中间层
- 后处理与跨作品层的输入，而不是输出终点

## 当前最重要的经验

### 1. 长篇是分水岭

短篇与中篇可以证明方法“能跑”，但只有长篇才能暴露真实问题：

- 图规模是否还能用
- 关系描述是否过肥
- token 是否失控
- provider 是否稳定
- 可视化是否到达上限

《连城诀》之后，整图 HTML 已经明显接近可用上限；《天龙八部》《倚天屠龙记》《鹿鼎记》进一步证明，后续人工分析必须转向子图、主题视图和 query，而不能继续依赖全图直看。

### 2. 清洗是必要前置，不是可选优化

长篇原文如果不先清洗，下载站残留、合集前言、版权说明、网址和格式噪声会直接污染图谱。

当前共识：

- `clean-text` 是长篇正式建图前的标准前置步骤
- 清洗只处理明显噪声，不做语义删改
- 清洗不是后处理替代品，也不负责修复实体和关系理解错误

### 3. 图谱查询的价值是“约束回答”，不是“替代模型”

当前 query 机制的本质是：

- 图谱负责缩小搜索空间、组织证据、暴露关系骨架
- 正文 chunk 负责提供可追溯依据
- 查询模型负责把证据写成分析结果

因此它不是纯图数据库推理，也不是让模型自由发挥，而是“证据受约束的 GraphRAG 文学分析”。

### 4. 当前系统已经优于纯统计 NLP，但还没有到终局

和传统词频、词云、共现分析相比，当前图谱底座的提升在于：

- 有实体类型
- 有关系类型
- 能做路径与邻接分析
- 能回到正文证据
- 能支撑跨作品研究问题

但当前它仍然存在：

- 别名分裂
- 复合关系边
- 少量跨作品污染
- 大图浏览困难

所以它已经“比传统 NLP 更有研究价值”，但还不能替代后处理与研究设计。

## 当前方法与过程共识

### 建图主流程

当前稳定流程已经收敛为：

1. 原文下载或准备
2. `clean-text`
3. `index`
4. `normalize-graph`
5. `audit-graph`
6. `visualize`
7. `report`
8. 视情况追加 query / eval / 子图

长任务优先使用远端 worker，以 `screen` 持久会话方式执行，再将结果回传本地。

### 远端 worker 的实践价值

这套远端流程已经被证明是可行的，关键好处有：

- 本地关机不影响远端长任务继续执行
- 可以作为“真正的 worker”长期复用
- 可跨会话、跨 agent 接续查看与回传结果
- 运行结果最终仍回到本地 `runs/`，保持项目内单一资产目录

### 中文路径问题的处理

远端任务中，中文相对路径偶发不稳定。当前可行规避方式是：

- 原始文件可以保留中文名
- 真正执行 `index` 时，远端复制一个 ASCII 文件名副本
- `screen` 任务使用绝对路径启动

这不是理论洁癖问题，而是实际降低长任务中断风险。

## 模型与成本经验

### 当前两条主路线

当前默认主路线仍然是：

- `deepseek-v4-flash-zh-strict-bge-m3`
- `doubao-seed-1.6-bge-m3`

但随着长篇跑完，结论比之前更清楚了。

### DeepSeek 路线

优点：

- 主干人物与主干关系更稳
- 跨作品污染更少
- 更适合作为高质量样板图谱底座

问题：

- 默认路线 completion 膨胀严重
- 成本高
- 描述更容易变成长摘要而不是干净边

### DeepSeek no-thinking 路线

这是本轮最重要的实用优化之一。

在长篇上已经验证通过：

- 《天龙八部》：`3742 / 6114`，约 `3.28h`
- 《鹿鼎记》：`3907 / 5841`，约 `3.75h`

并且从 token 结构看，`no-thinking` 显著降低了 completion 压力。

例如：

- 《射雕英雄传》默认 DeepSeek：completion 占总 token 约 `59.14%`
- 《天龙八部》DeepSeek no-thinking：约 `30.76%`
- 《鹿鼎记》DeepSeek no-thinking：约 `30.69%`

这说明 `no-thinking` 不是表面小优化，而是长篇可持续执行的关键改进。

### Doubao 1.6 路线

优点：

- token 效率明显更高
- 适合快速铺完整个 corpus
- 已在多部长篇上跑通，正式可用

问题：

- 更容易出现关系标签漂移
- 更容易出现少量跨作品污染或先验混入

因此更准确的定位是：

- Doubao 1.6 更适合第一阶段铺底座
- DeepSeek 更适合做少量高质量样板或后续重点作品对照

### 其他模型的结论

本轮试过的其他模型大多没有进入主线：

- Doubao 2.0 Lite：可用，但关系泛化更明显
- Doubao 1.5 Pro 32K：不推荐作为日常 index
- SiliconFlow DeepSeek V3.2 Pro：可跑通，但作为结构化抽取主力不如 V4 Flash
- SiliconFlow DeepSeek V4 Flash：可作为备用路线，但长篇正式任务稳定性不如已验证主线

结论不是“便宜模型都不行”，而是：在结构化抽取任务里，稳定、克制、遵守 schema 往往比“更强的综合写作能力”更重要。

## 当前结果的质量边界

### 已经可信的部分

当前图谱大致可以相信：

- 核心人物覆盖
- 主干组织、地点、武功、物件覆盖
- 大部分主要关系的存在性
- 作为 query / 子图 / 主题裁剪的基础结构

### 仍需谨慎的部分

当前仍需谨慎对待：

- 别名未合并的人物统计
- 单边承载过多语义的复合关系
- 边缘节点的过度连边或泛关系
- 少量跨作品污染实体
- 直接把整图当“终版知识库”来做严肃结论

因此目前最合理的工作方式是：

- 把图谱当材料底座
- 让研究结论建立在子图、证据、后处理和具体 query 上
- 不直接把原始整图当作最终学术结论

## 为什么这轮工作是值得的

如果只看花费，这轮实验确实不便宜。  
但从方法资产角度看，这轮最有价值的不是某一个 `graph.html`，而是以下积累：

1. 一整套长篇可执行流程
2. 一套可复用的远端 worker 方式
3. 一套对模型、provider、prompt、成本的实测经验
4. 一批已经成型的全集级图谱资产
5. 一组明确的后处理与研究方向

换句话说，这轮工作的真正产出不是“15 本书的图”，而是：

- 方法论
- 流程资产
- 模型经验
- 中间层数据资产

这些都可以迁移到古龙、刘慈欣、歌词、唐诗，甚至非文学语料。
