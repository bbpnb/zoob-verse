# 金庸图谱评测集 v1 学生报告

## 执行摘要

本报告完成了金庸图谱评测集 v1 的设计与试跑。共设计 30 个评测问题，覆盖 8 个分类，每类至少 3 题。实际试跑了 6 个问题，验证了查询脚本的可用性和图谱数据的证据密度。核心发现：图谱在人物关系和跨书比较方面好用，但在关系类型归一、时序建模、地点结构化方面存在明显局限。

## 评测集设计原则

1. **证据可追溯**：每个问题的 `suggested_queries` 必须能实际跑通，`expected_evidence_signals` 必须存在于图谱中（已在试跑中验证）。
2. **失败模式可检测**：每个问题列出 3 个 `failure_modes`，便于后续自动或人工评估。
3. **难度梯度**：`easy` 侧重单书直接查询，`medium` 需要跨实体比较，`hard` 需要综合推断和边界识别。
4. **不脑补**：`insufficient_evidence_boundary` 类问题明确要求 agent 指出图谱不足，而非硬编答案。
5. **候选与事实分离**：`crosswork_candidate_review` 类问题强制区分 `candidate_kind` 类型，不把候选当事实。

## 试跑结果

### 试跑 1：Q1 — 令狐冲与岳不群师徒决裂（single_work_relationship）

- **使用的命令**：
  - `relations --work 笑傲江湖 --name 令狐冲 --top 12`
- **关键证据**：
  - 令狐冲→岳不群 weight 253（全图最高），描述涵盖"自幼被收录→怀疑剑谱→逐出师门→生死搏杀"
  - 令狐冲→华山派 weight 199，"从归属到被逐"的完整弧线
  - 令狐冲→盈盈 weight 145，情感归属从华山转向魔教
  - 令狐冲→风清扬 weight 47，独孤九剑提供另一套武学秩序
- **草拟答案摘要**：令狐冲与岳不群的破裂不是简单背叛，而是师门伦理、个人自由和权力算计逐步撕裂。图谱捕获了从华山弟子→被逐→独立江湖人的完整身份变化链。
- **发现的问题**：关系 type 全部为"传授"，不能区分师徒、敌对、传授等细粒度类型。weight 253 的证据密度极高，但 type 字段丢失了语义信息。

### 试跑 2：Q2 — 韦小宝与康熙多重身份（single_work_relationship）

- **使用的命令**：
  - `relations --work 鹿鼎记 --name 韦小宝 --top 12`
- **关键证据**：
  - 韦小宝→康熙 weight 256，描述涵盖"主仆、朋友、师徒、君臣"多重身份
  - 韦小宝→天地会 weight 143，"双重身份矛盾"
  - 韦小宝→陈近南 weight 96，师徒+天地会上下级
  - 吴三桂→韦小宝 weight 69，敌对+互相算计
- **草拟答案摘要**：韦小宝与康熙的关系从"小玄子/小桂子"的摔跤朋友，发展为君臣心腹，再到立场对立。图谱通过 weight 256 的高密度描述捕获了这一演变。
- **发现的问题**：关系 type 为"传授"不准确，实际是多层身份叠加。图谱的 type 字段对复杂关系的表达能力不足。

### 试跑 3：Q3 — 萧峰与阿朱（single_work_relationship）

- **使用的命令**：
  - `relations --work 天龙八部 --name 萧峰 --top 12`
- **关键证据**：
  - 萧峰→阿朱 weight 79，"情深意重、命运悲怆"，误杀细节完整
  - 萧峰→丐帮 weight 35，"从统领到敌对"
  - 萧峰→雁门关 weight 23，人生起点和终点
  - 萧峰→耶律洪基 weight 46，"从深厚情谊到最终决裂"
- **草拟答案摘要**：阿朱之死是萧峰身份危机的催化剂。图谱清楚记录了"丐帮→契丹→阿朱→雁门关"这条悲剧链。
- **发现的问题**：阿紫 weight (118) 高于阿朱 (79)，可能因为阿朱早逝后文本量较少。这是图谱权重的一个偏差——weight 反映文本出现频率，不一定是关系重要性。

### 试跑 4：Q24 — 狄云地点迁移（plot_setup）

- **使用的命令**：
  - `relations --work 连城诀 --name 狄云 --top 12`
- **关键证据**：
  - 狄云→丁典 weight 73，狱中传授神照经
  - 狄云→水笙 weight 57，误解→信任→依恋
  - 狄云→雪谷 weight 12，受困→练功→归隐
  - 实体描述中包含"麻溪铺→江陵→狱中→雪谷→归隐"的迁移线索
- **草拟答案摘要**：图谱通过实体描述间接支持狄云的迁移路径，但没有显式的时序或独立的"迁移"关系类型。需要从描述中抽取地点信息。
- **发现的问题**：地点信息被埋在实体描述的长文本中，而不是结构化的关系。图谱无法自动回答"狄云去了哪些地方"这类问题。

### 试跑 5：Q22 — 天龙八部误认身份（plot_setup）

- **使用的命令**：
  - `search --work 天龙八部 --q 易容 --top 10`
- **关键证据**：
  - 阿朱实体描述中明确提到"精通易容乔装之术"
  - 存在"易容改装"和"易容神技"概念实体
  - 萧峰→易容改装 weight 1，"用面粉和胶水易容改装以隐藏身份"
  - 搜索返回 17 条结果，覆盖度有限
- **草拟答案摘要**：图谱通过阿朱实体描述直接支持"易容"叙事机制，但"误认身份"作为更广泛的模式（还包括段誉身世错位），图谱只通过实体描述间接支持。
- **发现的问题**：搜索"易容"返回结果较少，覆盖度有限。段誉身世错位需要从实体描述中抽取，没有独立的结构化支持。

### 试跑 6：Q30 — 张无忌地理迁移（insufficient_evidence_boundary）

- **使用的命令**：
  - `relations --work 倚天屠龙记 --name 张无忌 --top 12`
  - `search --work 倚天屠龙记 --q 冰火岛 --top 5`
- **关键证据**：
  - 实体描述中提到"冰火岛→蝴蝶谷→翠谷"等地点
  - 张无忌→胡青牛 weight 42，蝴蝶谷学医
  - 张无忌→九阳神功 weight 61，翠谷发现
  - 但关系列表中地点实体极少，top 12 中没有独立地点节点
- **草拟答案摘要**：图谱的实体描述中包含了张无忌的地点迁移线索，但关系层没有独立的"迁移"关系，无法自动还原完整路径。需要原文复核。
- **发现的问题**：这是图谱的结构性局限——地点信息被埋在实体描述中，而非结构化的关系层。

## 当前图谱好用的地方

1. **人物关系网络密度高**：核心人物的关系 weight 分布合理，能通过 top-N 快速定位关键关系。令狐冲 825 条关系、韦小宝 1323 条关系，密度足以支撑文学分析。
2. **实体描述信息丰富**：实体 description 字段包含大量情节摘要，即使关系层缺失，也能从描述中抽取证据。
3. **跨书人物索引可用**：`global/people.json` 的 `appearance_count`、`max_degree`、`appears_in_novels` 字段足以支撑跨书比较。
4. **跨书候选分类清晰**：`crosswork_people.json` 的 `candidate_kind` 字段（`continuous_work_shared` / `cross_corpus_suspect` / `shared_reference_review`）为人工复核提供了结构化入口。
5. **查询脚本好用**：`query_jinyong_graph.py` 的 `person`、`relations`、`search`、`top-people`、`crosswork` 命令覆盖了大部分常用查询场景。

## 当前图谱不足的地方

1. **关系类型过于粗糙**：绝大多数关系 type 为"传授"、"关联"、"影响"、"使用"，无法区分师徒、敌对、夫妻、利用、联盟等细粒度类型。这限制了统计分析和精确检索。
2. **权重反映文本频率而非关系重要性**：阿紫 weight (118) 高于阿朱 (79) 就是一个例子——阿朱早逝导致描述文本较少，但阿朱对萧峰的重要性远高于阿紫。
3. **没有时序建模**：图谱是静态的，无法自动回答"关系如何演变"或"事件先后顺序"。需要从描述中手动抽取。
4. **地点信息非结构化**：地点实体存在，但与人物之间的关系不是结构化的"出没于→时间点"格式，而是埋在描述文本中。无法自动还原迁移路径。
5. **武功/物件与人的关系类型单一**：独孤九剑、辟邪剑谱、屠龙刀等物件与人的关系多为"使用"或"传授"，没有区分"争夺"、"传承"、"修炼"、"觊觎"等类型。
6. **描述过长导致信息密度不均**：韦小宝实体描述 935 字符，某些小人物只有 10-20 字符。长描述包含大量信息但难以快速抽取关键证据。

## 对 skill 的改进建议

1. **增加 `neighbors` 命令**：当前 `relations` 返回某人的所有关系，但缺少"给定一个实体，列出所有与之相连的实体"的快速命令。建议增加 `neighbors --work <作品> --name <人物>`。
2. **增加关系类型过滤**：`relations` 命令应支持 `--type <类型>` 过滤，例如只看"传授"或"影响"关系。
3. **增加实体描述摘要**：对于超长描述（>500 字符），查询脚本应提供 `--summarize` 选项，返回 AI 摘要而不是完整原文。
4. **`search` 应支持跨作品搜索**：当前 `search --work <作品>` 限定单书，但像"九阴真经"这类跨书物件需要不加 `--work` 的搜索——这一点已经支持（`search --q <关键词>` 不加 `--work` 即可），但需要在文档中更明确。

## 对后处理的改进建议

1. **关系类型归一化**：这是最值得投入的后处理工作。建议先用抽样实验（100 条关系）验证分类器效果，再决定是否全量重构。
2. **增加"事件"层**：将关键事件（如"误杀阿朱"、"黑木崖之战"、"聚贤庄大战"）提取为独立实体，与人物形成"参与"关系。这能解决时序和部分"误认身份"问题。
3. **地点关系结构化**：为"出没"关系增加时间标签或章节标签，使地点迁移路径可计算。
4. **权重校准**：考虑引入"关系重要性"评分（基于关系描述的语义重要性），而不是单纯基于文本频率。

## 给 Codex 审阅者的问题

1. **评测集问题难度分布是否合适？** 当前 easy:medium:hard 约为 5:16:9。是否需要更多 hard 题来测试 agent 的边界识别能力？
2. **`insufficient_evidence_boundary` 类问题是否够强？** 当前 3 题分别测试感情转折点判断、主观判断（命运悲惨）和地理路径还原。是否还需要增加"武功细节"或"对话原文"类不足问题？
3. **是否应该增加一个"对抗性"问题？** 例如问一个图谱明显不支持的问题（如"张无忌和韦小宝谁武功更高"），测试 agent 是否会拒绝回答而非硬编。
4. **查询脚本的 `check` 和 `summary` 命令输出格式是否适合作为评测的标准输入？** 当前输出是 JSON 格式，但部分命令输出较大，可能需要限制输出长度。
