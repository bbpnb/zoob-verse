# 文学图谱的价值场景

本文记录当前阶段对 zoob-verse 的反思：我们为什么要费力构建小说知识图谱，以及什么场景能体现它相对“直接把全文丢给大模型”的价值。

## 当前判断

图谱不是为了替代阅读，也不是为了让一次问答更便宜。它的主要价值在于把长文本沉淀成可复用、可检索、可比较、可审计的结构化材料。

如果只想对一篇短文问一两个总结题，图谱通常不划算。长上下文直读更简单。

如果目标是长期研究、反复查询、跨作品比较、主题挖掘或内容生产，图谱才开始有意义。

## 最值得投入的场景

### 1. 反复查询同一批作品

一次 index 的成本较高，但后续可以反复复用。

适合的问题：

- 某个人物在不同事件中的动机如何变化？
- 某个物件如何贯穿主线？
- 哪些边缘人物实际推动了关键转折？
- 这个作品有哪些适合做内容选题的路径？

直接全文问答每次都要重新读全文。图谱可以把实体、关系和证据先组织好，降低后续探索成本。

### 2. 跨作品比较

这是图谱最有潜力的方向。

例如：

- 金庸作品中的女性英雄谱
- 佛教、道教、儒家观念在不同作品中的出现方式
- 父子、师徒、情侣、君臣关系的结构差异
- “宝物争夺”“身份错认”“复仇”“归隐”等母题的跨作品演化
- 不同作品中权力、武力、情感之间的关系模式

直接长上下文很难一次容纳多部大部头。图谱可以先把每部作品压缩成结构化索引，再做跨作品查询和比较。

### 3. 发现间接线索

文学分析里真正有意思的东西往往不是最显眼的主角关系，而是弱连接和间接影响。

例如：

- 一个小物件如何触发身份确认？
- 一个边缘地点如何改变人物相遇？
- 一个典故或象征如何提示主题？
- 一个看似喜剧化人物如何推动主线？

这类问题需要在人物、事件、地点、物件、概念之间跳转。图谱比纯 chunk 检索更适合暴露这些路径。

### 4. 内容生产与选题

图谱可以帮助把作品拆成可讲述的路径。

例如：

- “人物 A 如何因事件 B 走向结局 C”
- “一件宝物如何串起五组人物”
- “一个反派如何推动主角感情线”
- “最适合短视频讲述的三条剧情路径”

这类任务不只是回答事实，而是要找结构、看冲突、形成可表达的叙事线。图谱在这里更像选题地图。

### 5. 可审计的研究过程

直接问大模型，答案好看但来源常常不透明。

图谱工作流可以保留：

- index 模型
- query 模型
- embedding 模型
- 图谱版本
- 查询参数
- 召回实体、关系和 chunk
- token 和成本

这对调研项目很重要，因为我们不仅关心答案，也关心答案是怎么来的，以及同一个问题换模型后差异在哪里。

## 不值得用图谱的场景

- 只需要全文摘要
- 只问一两个简单事实题
- 文本很短，全文可以直接放进上下文
- 目标是文学评论成稿，而不是材料组织和证据检索
- 图谱质量不足，孤岛和泛关系太多，导致查询反而更混乱

这些场景下，direct-analyze 或普通 RAG 更直接。

## 对当前项目的启发

zoob-verse 不应该只停留在“建图指标好不好”。后续应该逐步转向“图谱能帮我们做哪些研究”。

建议把后续工作分成两条线：

1. 基础设施线：继续优化 index 质量、query 预算、模型选择和可视化。
2. 研究应用线：开始用已有图谱做具体主题研究。

研究应用线可以先从小而清楚的问题开始：

- 《越女剑》和《鸳鸯刀》中，女性角色分别如何推动主线？
- 两部作品中的“兵器/宝物”分别承担什么叙事功能？
- 哪些边缘人物对主线有间接但关键的影响？
- 两部作品中“无敌”的含义是否不同？

这些问题能检验图谱是否真正有用。如果图谱只能生成漂亮图表，但不能帮助提出更好的问题、找到更好的路径、组织更可靠的证据，那么它的价值就有限。

## 下一阶段成功标准

后续不只看节点数、边数、孤岛率，也要看：

- 是否能减少人工翻全文的时间
- 是否能发现 direct-analyze 不容易主动提到的线索
- 是否能支撑跨作品比较
- 是否能把主题研究材料组织成可复用视图
- 是否能给内容选题提供明确路径

如果这些指标开始成立，图谱才算真正值得继续投入。
