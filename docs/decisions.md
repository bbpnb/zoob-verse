# Decision Log

记录项目关键决策及其理由。

---

## 2026-04-24: 项目命名

**决策**：项目命名为 `graph-lore`

**理由**：
- `graph` — 体现核心技术（知识图谱、图分析）
- `lore` — 指"传说、知识、特定领域的知识体系"，涵盖文学、影视、游戏等
- 不局限于"文学"，唐诗、美剧、游戏世界观都能装进来
- 简洁、好记、有辨识度

**备选**：`literary-research`（太宽泛、偏学术）、`world-graph`（可能误解为地理）

---

## 2026-04-24: 统一平台 vs 分散项目

**决策**：采用统一平台（Framework + Plugin），而非每个作品独立项目

**理由**：
- 核心代码复用（图引擎、CLI 框架）
- 单一依赖管理
- 跨作品分析天然支持
- Skill 与项目统一管理

---

## 2026-04-24: 模块独立 Schema

**决策**：各模块独立定义实体/关系类型，不共享统一 schema

**理由**：
- 不同作品的研究维度完全不同（武侠 vs 科幻 vs 诗歌）
- 提取逻辑、分析方法、输出形式都不同
- 不能假设一套接口处理所有内容

---

## 2026-04-24: Skill 放在项目内

**决策**：Skill 放在 `.ai-skills/` 目录下，与项目一起版本管理

**理由**：
- 单一真相源，不用两边同步
- Git 跟踪版本历史
- 跨 AI Agent 可复用（symlink 接入）
- 克隆项目就有完整的方法论文档

---

## 2026-04-24: CLI 作为唯一对外接口

**决策**：项目只暴露 CLI 接口，Skill 只需知道如何调用 CLI

**理由**：
- Hermes 的 terminal 工具天然适配 CLI
- Skill 不需要了解内部实现
- 跨平台可复用（VS Code、脚本、cron job 都能用）
- 测试友好
