# 叙事文本知识图谱分层工作台设计

## 背景

当前项目已经验证了一个事实：LightRAG 图谱本身有用，但真正有价值的不是“把小说建成图”，而是把图谱作为研究底座，支持可复现的文学挖掘、跨作品比较和内容选题。

现有 `越女剑` 实验也暴露出一个关键问题：核心图谱如果承载过多分析目标，会出现 schema 过度膨胀、实体类型不稳定、不同作品无法复用的问题。因此需要将“图谱本体”和“分析层”分开。

## 目标

- 保留一个稳定、可复用、可证据化的核心图谱。
- 在核心图谱之上增加事件层、分析标签层和作品 profile。
- 支持金庸作品，也支持科幻、非虚构、其他叙事文本。
- 让后续的女性英雄谱、宗教意象、跨作品比较等任务都能在同一套工作台里完成。

## 非目标

- 不把所有专题分析都硬编码成实体类型。
- 不做“一套固定 schema 适配所有文本”的死设计。
- 不重构成纯 Web 产品，CLI 和研究目录仍然是主入口。

## 分层设计

### 1. 核心图谱层

这一层只保留最稳定的对象：

- 人物
- 组织
- 地点
- 事件
- 物件
- 概念
- 作品
- 证据

要求：

- 跨作品尽量一致。
- 实体和关系必须能从原文中找到证据。
- 不把分析视角塞进核心类型。

### 2. 事件层

事件是叙事驱动文本的关键中间层，但只收“推动情节和关系变化”的关键事件，不收琐碎动作。

建议保留的事件类型：

- 相遇
- 结盟
- 背叛
- 学艺
- 试剑
- 复仇
- 牺牲
- 战败
- 发现
- 出家 / 顿悟 / 参禅（按语料启用）

事件字段建议：

- 事件名
- 事件类型
- 参与者
- 地点
- 原因
- 结果
- 时间线位置
- 证据文本

### 3. 分析标签层

这一层不做硬 schema，做可挂载标签，用于专题研究和内容选题。

可复用标签例子：

- 女性角色
- 英雄原型
- 情感结构
- 权力结构
- 宗教意象
- 母题
- 价值冲突
- 跨作品联想
- 叙事阶段

标签可以挂在：

- 节点上
- 边上
- 事件上
- 路径上
- 整个作品上

### 4. 作品 profile

不同语料允许不同扩展，但不污染核心层。

例如：

- 金庸 profile：门派、武功、秘籍、兵器、宝物、称号、朝代势力
- 科幻 profile：文明、技术、飞船、实验、危机、星际组织
- 非虚构 profile：观点、论证、案例、政策、人物群体

profile 的作用是控制“哪些类型可以进入扩展层”，不是强行统一所有作品。

## 数据流

1. 原始文本进入索引流程。
2. LightRAG 生成原始图谱。
3. 本地规范化层合并别名、清洗英文 schema、统一关系类型。
4. 事件抽取层从规范化图谱和证据中提取关键事件。
5. 分析标签层根据规则或低成本模型进行标注。
6. 派生视图生成专题结果，例如：
   - 女性英雄谱
   - 佛教意象链
   - 因果链
   - 跨作品对比报告

## 查询策略

查询阶段不再只看“图能不能答”，而是按问题类型选择不同路径：

- 事实型问题：图谱召回 + 轻量整理
- 因果链问题：事件层 + 图谱召回
- 专题问题：标签层 + 路径抽取
- 跨作品问题：统一规范名 + 作品 profile + 聚合分析
- 低置信度问题：允许 fallback 到 direct-analyze 对照组

## 成本与模型

- 索引模型和查询模型保持解耦。
- Embedding 先保持稳定，避免混入变量。
- rerank 先作为可插拔能力，不做默认依赖。
- 保持成本统计，所有运行都记录 token usage 和估算金额。

## 验证方式

先不重跑全量全集，优先用现有《越女剑》运行验证：

- 核心图谱是否稳定
- 事件层是否能抓住关键叙事链
- 标签层是否能支持女性角色、宗教意象、权力结构等专题
- 同一套机制是否能扩展到其他文本类型

## 风险

- schema 过宽，导致图谱变脏
- 事件粒度过细，导致数量爆炸
- 金庸 profile 被误认为通用 schema
- 分析层和本体层边界模糊

## 结论

项目应定位为“叙事文本知识图谱研究工作台”，而不是单纯的“小说建图脚本”。图谱本体要单纯，复杂分析放到事件层、标签层和派生视图中完成。
